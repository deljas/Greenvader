# グリーンベーダー AI開発チーム テンプレート

2026年10月14日版。Astraが設計・統合を担当し、Solが実装と独立検証、Lunaが記録更新を担当します。ゲーム開発はまだ開始していません。このフォルダは配布用テンプレートで、現在のCodex設定への適用は行っていません。

## 役割

| 担当 | モデル | 推論設定の初期値 | 責任 |
|---|---|---|---|
| 親エージェント | gpt-6-astra | high | 設計、作業分割、仕様整合、統合、最終判定、ユーザーへの報告 |
| green_implementer | gpt-6.1-sol | high | 指定範囲の実装、自己検証、修正 |
| green_verifier | gpt-6.1-sol | high | 実装者とは別の文脈で仕様から検証、再現、独立テスト |
| green_documenter | gpt-6-luna | high | 承認済み判断と実際の検証結果の転記、進捗と手順の更新 |

Solはこの環境で利用可能なGPT-6.1 Sol、LunaはGPT-6 Lunaを指定しています。GPT-6 Solを意図していた場合は、実装・検証の両ファイルを合わせて変更してください。利用できないモデルへ黙って代替せず、親へ報告します。推論設定はこの案件向けの初期案であり、性能保証ではありません。

実装と検証を同じモデルで行うため、モデル由来の盲点までなくなるわけではありません。重要な仕様境界はAstraも差分と証拠を確認します。

## 導入

1. ZIPを展開し、フォルダ内のファイルを開発リポジトリのルートへ配置します。Godotプロジェクトはそのルートで作成する想定です。
2. 既存のAGENTS.mdや.codex/config.tomlがある場合は、上書きせず内容を統合します。
3. Codexで親チャットのモデルをAstraに設定し、START_PROMPT.mdの本文を送ります。
4. 親は利用可能なサブエージェント機能、モデル指定、Godot起動手段を確認してから委任します。

同梱の `.codex/agents/*.toml` は公式のカスタムエージェント形式に沿った設定例です。アプリや組織の管理設定が優先されます。モデル名を文章に書くだけでは実際のモデル切り替えにはなりません。委任時の設定・ツール応答により確認できる範囲を記録してください。モデル確認のためだけにAI自身の自己申告を信頼しないでください。

カスタムエージェントを認識しない実行環境では、親が実際に提供されているサブエージェントAPIのモデル指定を使い、同梱の役割指示を依頼本文へ含めます。モデル指定に新規文脈が必要なら、履歴を引き継がず必要な資料とタスク票を渡します。設定可能な手段がなければ、希望どおりの分担が有効とは報告せず、制約を説明します。

権限は親から継承されます。文書の編集範囲は運用ルールであり、OSレベルのアクセス制限ではありません。今回のテンプレート作成では、TOMLの構文とファイル配置を検証しますが、実際のエージェント起動やアカウントごとのモデル利用可否は検証しません。

## 開発の順序

Astraのタスク定義 → Solの実装と自己検証 → 別のSolによる検証 → 必要な修正と再検証 → Astraの受入判断 → Lunaの文書更新 → Astraの記録確認。

常に4体を走らせる必要はありません。Lunaは一つの変更または段階がまとまった後に呼びます。テスト担当は実装中に検証計画を読取りで準備できますが、実行は対象差分が固定されてから行います。依存する作業を無理に並列化しません。

最初の開発範囲はP0〜P5。設計だけで止めず、起動できる成果を毎段階で作ります。通常の段階切替にユーザー承認は不要ですが、仕様・世界観・アート方針の変更などは既存の自律開発指示に従います。

## 資料

- `AGENTS.md`：チーム全体のルール。
- `.codex/config.toml`：親モデルと委任の設定例。
- `.codex/agents/`：実装、独立検証、文書更新の役割定義。
- `START_PROMPT.md`：Astraへ渡す開始指示。
- `TASK_TEMPLATE.md`：委任時の作業票。
- `docs/green-invader/`：既存の企画・技術方針・開発計画。

## 根拠と限界

これはモデルの役割特性に基づく運用提案で、このゲームで比較測定した優劣ではありません。公式説明でもSolは複数段階の作業、Lunaは範囲の明確な仕事に位置付けられています。文書更新でも設計判断が必要ならAstraへ戻します。
