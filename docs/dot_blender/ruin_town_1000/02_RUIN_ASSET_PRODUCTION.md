# dotへの指示 朽ちた町の追加アセット1000件

2026-10-18。既存素材と町は「滅びて間もない町」として保持し、長い年月で破損・腐食・倒壊した町を組める素材を追加制作してください。植物は別制作の作業待ちです。この依頼では新しい植物を作りません。

## 目的と優先順位

錆色のモデルを大量に増やすだけでは不十分です。低解像度でも、欠けた輪郭、落ちた部材、露出した構造、地面に堆積した破片から荒廃が読める形にしてください。新規制作1000件を目標とし、色替え・回転・鏡像・拡縮・seed違い・LOD・同じモデルの成長段階は別件に数えません。

既存の倒れた電柱PRP-004、錆車PRP-041、配送車PRP-042、平荷台トラックPRP-162、折れた鉄塔PRP-136等を先に確認し、同じ用途と輪郭の再生産を避けます。追加500件の建物/瓦礫境界/付属品も必要範囲で参照できますが、既存素材を今回の完成数に入れないこと。

## 制作方法と品質

モデル・材質・UV・レンダー・GLB書出しはメインがBlenderで行います。bpy、Geometry Nodes、共通生成関数は可。HTML作成・ファイル管理・転送には通常のスクリプトを使用して構いません。モデル制作を外部生成サービスやサブエージェントへ委任しないでください。

- 元の町を残し、軽度損傷・重度破損・骨格のみ等の構造差を作る。ただし色だけの劣化段階は件数に加算しない。
- 車輪がない車は適切に沈む/傾く。折れた柱には破断面を作る。落ちた部材は支えがなければ地面に置く。倒壊に理由が分かる造形にする。
- 壁・屋根・床の断面に厚みを与え、裏から見ると消える、内部が未処理、閉じた箱の表面に穴模様だけを貼った状態を避ける。
- 「壊れた本体＋対応する落下部材」を組めるよう、破断位置・材質・寸法・接続点・`set_id`を合わせる。1セットを1件と数えた場合、同梱部品を再度完成件数に加算しない。
- 植物、水面、本体、瓦礫を分離する。水たまりは輪郭/受け面のモデルと水面候補meshを分け、反射はGodot側で付ける。Blender画像の反射を素材へ貼らない。
- 電線は支点・終点・たるみ・接続向きをmetadataへ記録する。長さ違いだけの大量水増しをせず、切断/束/絡み/分岐等の用途差を作る。
- 道路や歩道はグリッドへ接続できる端を持たせる。1セル0.4mを基準とし、1×1以外に帯、内角/外角、2×2、4×2、4×4等を用途に応じて使う。主要物体を全て0.4m格子へ無理に変形させない。
- 模様は錆・塗装剥離・汚れなど素材自身の色差として作る。光源方向、投影影、AO、広域の明暗を焼き込まない。輪郭線なし。
- 全面に小さな点ノイズを散布して質感を代用しない。大きな形、中程度の欠損、少量の細部の順に優先する。
- 同一設定のマテリアルを共有し、幹や破片ごとに同じ材質を複製しない。組み合わせや破損切替に必要な分離は保ち、細かいメッシュの過剰分割を整理する。
- Blenderはm・Z上、GLBとmetadataのベクトルはm・ローカルY上。変換は`(x,y,z)→(x,z,-y)`。設置原点・接地面・壁への取付法線・必要な接続点を明示する。
- 自己完結した単純なglTF互換材質を使う。原則不透明、透過が必要なら二値cutout優先。実GLB再読込で色・法線・両面・頂点色・寸法を確認する。
- 小物100〜1500tri、車両/中型構造1000〜10000tri、大型キット合計15000tri程度を初期目安とし、超過は理由を記録する。材質数/mesh数/triangle数は実数を残し、性能保証にしない。

見た目の基準は、正投影仰角30°/方位45°、縦18.5m、640×360の直接レンダーとnearest整数3倍です。拡大画像だけで合格にしないこと。小物は拡大補助画像も付け、どちらの倍率か明示します。

各GLBの再読込・寸法・必要ファイル確認は各件。視覚確認は小ロットの一覧と代表画像で十分です。同じ不良を大量に増やさず、問題のある生成方式を調整してください。解消しない素材は`needs_fix`へ分け、完成数へ加えず他系統を進めます。

## 納品形式と配置見本

各素材フォルダへ、編集可能blend、GLB、必要画像、metadata.json、共通距離preview、一覧用previewを保存します。GLBに確認用の床・カメラ・ライトを混入させないこと。

metadataの最低項目は、`asset_id`、`name`、`category`、`pack_id`、`version`、用途、壊れ方、単位/座標系、GLBのAABB/寸法、原点、接地/接続情報、GLB/blend/previewのファイル名、triangle/mesh/material実数、`set_id`と関係ID、Blender再読込結果です。成長/衝突/ゲーム検証を実装していなければその状態を明記します。

「倒壊した交差点」「廃車のたまった駐車場」「屋根が落ちた商店街」の小さな配置見本を作ってください。使用IDとtransformを付け、元部品を再使用できる状態を保つ。配置見本は1000件へ加算しません。広大な地形やゲーム実装へ広げないでください。

## PC保存とHTML更新のタイミング

制作環境での安全保存と、PCへのまとめ納品を分けてください。**blend/GLB/metadata/進捗は制作側で各件ごとに保存**します。1時間待ってから初めて保存する運用は禁止です。

PCへのcheckpointは、次のどちらか一方が成立した時点で実施します。AND条件ではありません。

```text
pendingがある AND (
  前回の成功checkpointから実時間3600秒以上
  OR 前回の成功checkpoint以降に新規完成した一意IDが50件以上
)
```

- 初回は制作開始時刻を時間の起点とする。以降は成功checkpointの時刻を使用する。時間はゲーム内時間ではなく実経過時間、時刻記録はUTC等の明示された形式で統一する。
- 各素材の完成時と長い処理の安全な区切りで条件を確認する。1時間を越える長い処理では、保存可能な境界で既に完成している分を納品する。途中のGLBを無理に転送しない。
- 50件は一意の新規完成ID数。色替え・再転送・再描画・修正版・不良品を新規件数へ重複加算しない。修正版などの未転送変更も時間条件と最後の保存の対象にする。
- pendingがなければ空の保存を繰り返さない。初回HTML作成、終了・中断・利用枠到達の直前は、1時間/50件未満でも残りを保存してHTMLを更新する。
- 再開時にlast_successful_checkpoint、pending IDとhash、前回完了IDを読み、時計や件数をゼロから始めて未保存分を忘れない。

### checkpointの手順

1. 完成済みの転送対象と各ファイルのhashを確定し、checkpoint IDを付ける。
2. PCの今回専用フォルダへ差分転送する。新しいファイルは一時名/ステージングから確定し、前の正常なファイルを壊さない。同一hashは再転送不要。旧素材や他案件へ上書きしない。
3. PC側の実ファイル数・サイズ・SHA256を転送manifestと照合する。クラウド側の保存成功だけでPC保存済みとしない。
4. **同じcheckpoint内で指示書01のHTMLを更新する。** PCで検証済みの素材と画像だけを追加・更新し、未転送分や未完の予定IDを完成カードとして公開しない。既存素材も保持する。
5. ID/画像/リンク/件数を検査して新HTMLへ置き換える。追加分だけの差分更新とし、過去全件のサムネイルを毎回再描画しない。
6. PC確認とHTML更新の両方が成功したらcheckpoint成功時刻と対象IDを確定し、新規完成件数のカウンタをリセットする。RESUMEとcheckpoint履歴を更新し、次の制作へ進む。

PC転送だけ成功してHTML更新が失敗した場合は`pc_verified=true, catalog_pending=true`と記録し、全checkpoint成功扱いにしません。再試行では同じhashの素材を重複転送せずHTML更新を完了させます。転送中断や権限不足でも制作側の成果を保持し、未保存分を消さないこと。

制作側へ保存済み、PC確認済み、HTML反映済みを別状態で管理します。PCへアクセスできなければ正式なPCアクセス経路を確認し、未転送一覧を残します。利用可能な権限を捏造したり、Luna経由なら制限を回避できると判断しないでください。

## Lunaを使う場合

メインでできることはすべてメインで行います。PC保存・検証・HTML更新に必要な場合だけ、Lunaへまとまった1つのcheckpointを渡して構いません。転送担当とHTML担当を別々に細分化せず、可能なら同じLunaへ一括依頼してください。

毎checkpointで自動的に起動しないこと。必要なときに既存のLunaを再利用し、対象manifest・編集先・禁止事項を明示します。モデル制作、美術判断、最終の納品判定はメインが担当します。子から再委任せず、完了したLunaを理由なく待機させ続けないでください。

呼出し回数の固定上限は設けませんが、必要最小限とします。旧案件の「累計1回」制限は本依頼に適用しません。Lunaを指定できなければメインで続け、他モデルへ勝手に変更しないこと。メインとLunaで同じmanifest/HTMLを同時編集せず、checkpointの公開担当を1人に固定します。

## 進捗報告と終了

checkpointごとに短く、今回完成数/累計完成数、PC確認済み数、HTML反映済み数、needs_fix数、次の系統を報告してください。細かなロット承認や途中の美術返信待ちは不要です。

1000件の有効な新規素材と3配置見本、最後のPC保存・HTML更新が完了したら停止します。利用可能な環境/枠の制約で止まる場合は、できた分を最後に保存し、未完IDと具体的な次の操作を残してください。件数不足を完成扱いにせず、夜間の無期限稼働や所要時間を保証しないこと。定期実行、別チャット、有料外部サービスを勝手に追加しないでください。
