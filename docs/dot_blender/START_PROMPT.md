# 新しいdotへ貼る開始プロンプト

以下を本文として貼り、同じフォルダの `INSTRUCTIONS.md` と `ASSET_CATALOG.md` を読めるようにしてください。パスを読めない環境では2ファイルを添付します。

---

ゲーム「グリーンベーダー」用の3D素材を制作してください。添付の `INSTRUCTIONS.md` を制作仕様、`ASSET_CATALOG.md` を240件の候補一覧として読んでください。ローカル環境なら `C:/godot/greenvader/docs/dot_blender/` にあります。読めない資料や使えない機能を確認済みと扱わないでください。

目指すのは、廃墟と植物が共存する美しいポストアポカリプスです。輪郭線を付けず、3Dの硬い影と低解像度表示でピクセルアートに近い見た目を作ります。高解像度での精密さより、実際のゲーム相当の画面で用途・輪郭・葉の質感が読めることを優先します。

最優先の制作体制は次のとおりです。

- モデル・材質・UV・プレビュー・書き出しは、メインエージェントが扱うBlenderだけで行ってください。Blender内のbpy、Geometry Nodes、標準モディファイアは使えます。外部でのメッシュ生成、画像生成AI、外部3D生成サービス、他ソフトへの制作委任は行いません。
- サブエージェントは原則使わず、呼び出し0回で進めてください。どうしても必要な場合だけ、制作案件全体で最大1回、Lunaに一覧・納品記録の整理をまとめて依頼できます。モデリング・Blender操作・美術判断・合否判断はメインが担当します。
- 各モデルや各ロットでの呼び出し、並列委任、子からの再委任は禁止します。Lunaを実際に選択できるか確認し、利用できなければメインで続行してください。Sol/Astra等へ代替しないでください。再開しても呼び出し回数をリセットしません。
- この体制は今回の素材制作専用です。ゲーム開発側のエージェント分業を持ち込まず、既存ゲーム全体の規約も変更しないでください。自己確認を独立検証と呼ばないでください。
- 新しいチャット、定期実行、追加課金を自動で作らないでください。既存ゲームのコード・シーン・資産は上書きせず、新しい制作フォルダに保存してください。

まずBlenderの利用可否、バージョン、操作経路、保存先を確認してください。利用できない場合は具体的な不足を報告し、他の制作手段へ無断で切り替えないでください。

候補は建物60件、ツタ30件、コケ20件、樹木40件、地面と水たまり40件、景観小物50件、合計240件です。候補一覧を制作台帳に取り込み、件数とIDの重複を確認してください。単なる色替え・回転・LOD・成長段階を別件として水増ししないでください。候補数と完成数は分けて報告してください。

制作時は特に次を守ってください。

1. 確認画面は正投影、カメラ仰角30度・平面方向45度、縦18.5m相当の範囲、640×360の直接描画です。1920×1080に見せる場合はNearestで3倍にします。各モデルを画面いっぱいに拡大せず、実寸配置の可読性を確認してください。960×540の正式方針を変更する判断は行いません。
2. 素材へ光源方向・投影影・広範囲の明暗を焼き込みません。GLBへ渡せる単純な材質を基本にし、硬い影はライトで作ります。
3. 建物・ツタ・コケ・ひび・地面の草は独立した層にしてください。共通植物部品を異なる建物で再利用し、成長段階ごとの専用建物を量産しません。ツタには曲がり・横への広がり・分岐を、コケには大きさと不規則な輪郭の違いを持たせます。
4. 最大緑化でも壁の約50%以上が見える配置にします。ツタは窓枠を伝って窓の一部にかかってよく、扉の通路やひさしとの不自然な貫通は避けます。根元・枝の接続・受け面・開口部などを記録してください。
5. 地面は1セル0.4mの直交グリッドに沿わせ、複数サイズを用意します。土は草で覆えてよく、舗装はひび・目地から草が出ても素地を残します。内部の緑化率を変更する提案にはしません。
6. 水たまりは、水面と泥・石・落ち葉などを分離します。映り込みを描き込まず、水面識別名と高さを記録してください。ゲーム側で反射・受影の接続が必要です。
7. 樹木は非対称の樹冠、中程度の葉群、隙間、葉先を組み合わせて葉の質感を見せます。ひびや鉄筋も低解像度で消えない主な形に絞ってください。

最初は **BLD-001、VIN-007、MOS-006、TRE-001、GND-009、PRP-001** の6件を制作してください。同じ確認シーンに配置し、初期・中間・成熟の合成例、実寸640×360の画像、編集可能な `.blend`、描画用 `.glb`、必要なテクスチャ、接続用 `metadata.json` を提示してください。座標はBlenderのZ上と納品GLBのY上を区別し、寸法・原点・材質が書き出し後も保たれるか再読込で確認します。

この代表6件が完成した時点で、一度ユーザーの作風確認を受けてください。了承後は残りを最大12件の小ロットで進め、各モデルごとの確認待ちは不要です。次のロットには水たまりGND-036を含めてください。既存部品を使い回しながら240件の制作計画を進め、途中でまとめて大量の作り直しが発生しないようにします。

検証はほどほどにし、代表セットで基本方式を確認した後は通常光の実寸プレビューとGLB再読込を中心にしてください。Blenderでの確認とGodotでの確認は別です。Godotの性能・反射・影・ピクセルパーフェクト・緑化接続は、ゲーム側で確認するまで `NOT_RUN` と記録してください。

`production_manifest.csv` またはJSONに全候補の状態・出力先・版・三角形数・材質数・確認結果を残してください。`RESUME.md` には完了ID、途中の1件、次の操作、保存ファイル、Blender版、制約、Lunaの累計呼び出し回数を短く記録してください。中断時は保存して再開可能な状態にし、存在しない成果やゲーム統合済みという報告をしないでください。

まず資料の確認と制作環境の確認を行い、代表6件の制作に着手してください。
