# グリーンベーダー 開発モデルの選定

2026年10月14日時点の判断です。Godotでこのゲームを実装した直接比較試験は行っていません。以下は公式の用途説明と、今回の仕事の進め方からの推奨です。

## 推奨

費用と利用枠が同程度に許すなら、まずAstraを主担当にして、仕様から実装・検証まで一貫して進める案を推します。世界の成長、戦闘、自動化、保存、描画が互いに関係するため、複雑な条件の整合を保つことを重視した判断です。Godot開発でOpus 5.5より優れていると実証した判断ではありません。

OpenAIはGPT-6 Astraを複雑な推論、コーディング、コンピューター操作等に向けたモデルとして説明しています。[公式モデル情報](https://developers.openai.com/api/docs/models/gpt-6-astra)

Opus 5.5も有力です。Anthropicは長時間のエージェント型コーディングと知識作業向けと説明しています。Claude Code側でGodotの起動や検証環境が整っている場合や、継続利用できる枠が多い場合は、Opus 5.5を主担当にする合理性があります。[公式モデル情報](https://platform.claude.com/docs/en/models/opus-5-5/overview)

モデルの名称より、ファイル編集、Godot起動、ログ取得、実画面の確認、Windowsビルドの実行までできる実行環境が重要です。UIや画像を確認できる手段がない場合は、モデルを替えるだけで解決するとは限りません。

## 費用の読み方

確認した公式ページの標準API単価は、100万トークン当たりAstraが入力10ドル・出力50ドル、Opus 5.5が入力4ドル・出力20ドルです。キャッシュ、長い入力、実行モード等で条件が異なります。これはAPI単価であり、CodexやClaude Codeの契約内での利用枠や実際の開発費と同じではありません。単価だけで総費用や速度の優劣は決まりません。

従量課金で長時間回すならOpus 5.5の低い標準単価は判断材料になります。既存契約の枠で動かすなら、残りの利用可能量と実際の完了率を優先してください。上記数値の根拠は各モデルの公式ページです。

## 小さく比較する場合

同じ初期リポジトリの独立コピーで、P0とP1の限定課題を実施し、同じ条件で比べます。比較のために本開発を二重に長期間進める必要はありません。

- 起動まで自分で到達したか。
- 輪郭線なし・ピクセルパーフェクトを守ったか。
- 種まき、成長、資源の循環が実際に動いたか。
- 不具合を発見し、再現・修正・再確認したか。
- 確認していないことを正しく報告したか。
- 人間の介入回数、経過時間、利用枠／課金量はどの程度だったか。

主担当は一つに固定し、必要ならもう一方へ節目のレビューを依頼する運用が扱いやすいです。この資料の作成では、いずれのモデルにも開発依頼を送信していません。
