# ソース管理・ゲーム起動入口の方針

更新日: 2026-10-24

対象: PoC3以降

決定者: ユーザー

本書をソース管理と起動入口の運用方針の正本とする。過去版の別入口・別名前空間の記録は当時の履歴として保持し、今後の運用には本書を適用する。

## 合意した運用

- 通常起動用の入口はルートの `run_game.bat` 1本とし、最新の遊べるゲームを起動する。
- PoCの版はGitのコミットとタグで区切る。PoCごとにゲーム一式や通常起動batを複製しない。
- 個別の機能確認用batは、比較・検証に継続して使うものだけ `launchers/labs/` に残す。
- 役目を終えた起動batは、Git履歴に保存され復元可能であることを確認してから作業フォルダから除く。
- PoC3の壁打ち資料は、全論点の方針が固まる時点でまとめてコミットする。
- 実装は1機能単位を基本にコミットする。
- リモートへのpushはユーザーが行う。

## 整理作業の順序

1. 既存の起動ファイル、ソース、資料、試験用ファイルと未追跡成果を棚卸しする。必要な成果を保全し、削除対象は履歴から復元できる状態にする。
2. `run_game.bat` が最新の遊べるゲームを起動するよう通常入口を統一する。
3. 継続して用途のある試験用batを `launchers/labs/` に残し、役目を終えたbatは履歴保存を確認してから除く。
4. 起動案内と現役の参照先を実態に合わせて更新する。

整理時は既存の保存データを削除・上書きしない。残す試験用batと除くbatは、棚卸し後に決める。
