## 状態と担当

| 状態 | 意味 |
|---|---|
| 未着手 | 担当・予約なし。依存と競合を確認して取得できる |
| 作業中(codex) | Codex親が取得。担当セッションを必須記入 |
| 作業中(claude) | Claude親が取得。担当セッションを必須記入 |
| 検証待ち | 実装凍結。元担当が予約を保持し、独立検証を手配 |
| 保留 | 未完了で停止。引き継ぎと子の停止を記録して予約解除 |
| 完了 | その票の合格条件を親が確認。担当予約解除。未検証は別票へ明示 |

`担当ツール` は `codex` / `claude` / `なし`。`担当セッション` は実際のチャットID、または `claude-20261014-p0check` のような一意な呼び名。モデル名とツール名を混同しない。完了・保留時は担当を `なし` にして最終担当と履歴に旧担当を残します。

Claudeが未着手票を取得する場合の管理欄の例（実際の範囲を必ず埋める）:

```markdown
- 状態: 作業中(claude)
- 担当ツール: claude
- 担当セッション: claude-20261014-p0check
- 予約中の編集範囲: tests/independent/p0_verify.gd、evidence/p0-verify/
- 予約中の共有資源: Godot importと検証プロセス
```

Codexなら状態を `作業中(codex)`、担当ツールを `codex` にします。親が担当を引き継ぐ際は、ラベルだけを書き換えず、下記の停止・引き継ぎ手順を完了してください。

## 取得・実装・引き継ぎ

1. AGENTS.md、docs/STATUS.md、DECISIONS.md、作業票、`git status --short` と実差分を読む。未コミット差分は他者の成果かもしれないため破棄しない。
2. 他の作業中・検証待ち票も読み、編集範囲と共有資源を照合する。両ツールで同じフォルダを開くのが基本。別worktreeならそのパス・基準コミット・統合担当も記録し、古い票を同期せず取得しない。
3. 親が管理欄の状態、担当、セッション、実際の予約範囲、更新日を先に記入する。単に票を読んだだけでは取得にならない。タスク一覧確認例: `rg -n '状態:|担当ツール:|予約中' tasks`。
4. 子の編集担当は親がさらに分割する。実装と独立検証は別エージェント。子は同じ親のタスクIDを使い、他の票を勝手に取得しない。
5. 実装を凍結してコミットまたはハッシュと差分を記録し、`検証待ち` にする。検証者はゲームを直さず失敗を返す。修正するなら親が作業中へ戻し、影響範囲を再検証する。
6. 完了時は証拠・実結果・残課題・次の一手を記載し、親が合否判断。中断なら `保留` にして担当を解除する。移譲先は停止済み・解除済みを確認後に自分の担当を記入する。

これはMarkdownによる協調運用で、同時取得を原子的に防ぐロックではありません。別タスクでも同じファイルを予約した場合、両方が着手せず担当を調整してください。更新時刻が古いだけで他方の担当を奪わないでください。担当と連絡が取れなければユーザーへ確認します。

共有資源は `project.godot`、シーン、素材・import設定、`.godot/` のimport、Godot実行ウィンドウ、セーブ試験領域、Git index/コミット、共有進捗文書など。検証待ちの実装を他ツールが変更しない。Git操作は親一人が実行し、起動中のゲームを自分のものと推測して終了しない。
