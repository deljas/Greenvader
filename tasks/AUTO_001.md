## 自律運用の手順

1. 親（Opus）が次の子票を読み、競合（Codex・他セッションの予約、共有資源）を確認してから、管理欄を作業中(claude)にし、予約範囲を記入する。
2. 実装は green-implementer（Sonnet）。子票の範囲だけを渡す。
3. 独立検証は、別の呼出しの green-verifier（Sonnet）。不具合は実装者へ戻す。
4. 親が差分と証拠を確認して受け入れる。その後、子票ごとに master へコミットする（作者 `Claude Code <claude@local.invalid>`、git設定は変えない）。
5. 文書（STATUS / DECISIONS / VALIDATION / ASSETS / BACKLOG）は、段階の区切りごとに green-documenter（Haiku）へまとめて依頼し、親が確認する。
6. 段階票（P1〜P5）は、子票がすべて合格したら親が完了にする。その後、止まらずに次の段階へ進む。

検証の方法:
- ロジックはheadlessで検証する。描画はGPUウィンドウで確認し、入力はエンジン内で注入する。
- Godotのウィンドウは、なるべく副モニタに出して回数を抑える。起動時にOSのフォーカスを得ることがある点は既知の制約（BACKLOG）。
- 物理入力の確認と楽しさの評価は代行しない。STATUSの「ユーザー確認待ち」に積み、非同期で依頼する。

## 自律では進めず、止めて相談すること

- 確定仕様、世界観、アート方針の変更。必須機能の削除。エンジンの変更。
- 支払い、外部公開、外部へのアップロード。外部ソフトウェア・素材の取得（音は自作で生成する）。
- 書き出しテンプレートの導入（ユーザー指示により後回し）。
- ユーザーの実入力を乗っ取るテスト。ユーザーの既存セーブや制作物を失う変更。
- Codexや他セッションの予約との競合、担当不明、引継ぎ不足。
- 仕様の解釈で結果が大きく変わる曖昧さ。この場合、関係のない子票は先に進める。

## 親が決めた実装初期値（仮。調整データに置く）

- 地域: 4pxタイル・512×512タイルの手作り地域。地形マップは1px = 1タイルのPNGで作り、凡例をデータに置く。描画はタイルごとのNodeではなく、区画ごとの画像を変化したところだけ更新する。P0の景観（川・廃墟・木々の構図）は開始地点付近の見た目として再利用してよいが、緑化対象の定義には使わない。
- 段階: 空き → 種（選んだ位置に1pxの点）→ 芽1（1×1px、ここから発芽済みとして緑化率に数える）→ 芽2（縦2×横1px）→ 成熟（タイル全体を緑で塗る）。成熟の緑は一色で、色は調整データに置く。斜めの隣接は縁の判定に使わない。
- 種の回収: 成熟植物が一定間隔で種の実を落とし、主人公が近づくと自動で回収する。Eキーは「調べる・展望」用に空けておく。
- 植物の選択: 通常・にんじん・キウイを、マウスホイールとTabで切り替える。にんじん・キウイも通常の種を消費する（コストは調整値）。
- 安全地帯: 破壊されない種の供給源を置き、種ゼロから回復できるようにする。
- HP: P1で最小限のHPと表示を導入する（キウイの回復対象）。被ダメージはP2から。
- 天候キー1/2/3: P0の試作操作。P4で本物の天候に置き換え、開発用の操作へ格下げする。
